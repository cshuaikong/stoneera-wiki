## 先确认你想移除的是什么

区分未完工订单、已经完成的墙、仍列在项目列表中的完工建筑，以及可以移动的家具。来源对这些状态给出了不同操作。若只寻找一个通用 Deconstruct 按钮，反而可能错过与当前对象和实际目标相符的功能；取消、拆解和移动不是同一个结果。

![原创取消订单、拆除与移动的状态示意图，非游戏画面](/images/articles/deconstruct-and-move.webp)

[原拆墙讨论](https://steamcommunity.com/app/5057770/discussions/0/568174304851704793/)创建于10月14日。后来另一位玩家追问已经完成的墙怎么拆，开发者于10月30日 UTC 回答 **Mining**，玩家之后确认有效。不能把最新回复日期当成整个主题的创建日期，也不能把它当成新的发售公告。

## 不同状态应该选择什么动作？

采用针对目标有明确依据的操作。Demo 0.9.18 支持单个订单的查看与取消；[0.9.16 公告](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1846651706689993)则另外说明了家具移动和保留的完工项目拆解。这样可以避免为了停止一个订单，却误把已有建筑的大范围区域一起当成目标。

| 对象与目标 | 已有依据的操作 |
| --- | --- |
| 停止未完工施工订单 | 查看并取消该单个订单。 |
| 移除已经完成的墙 | 按开发者的具体回复使用 Mining。 |
| 拆掉仍保留在列表中的完工建筑 | 使用项目拆解支持；资源回收有说明，但比例未固定。 |
| 换个位置放完工家具或木工台 | 使用其支持的移动功能，不必先假设一定要摧毁。 |
| 重用设计或复现支持的设置 | 进入独立的计划、Copy 或 Clone 流程。 |

[0.9.15 说明](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1846018067942304)中的 **Clear Area** 可以取消订单并移除可放置对象，返还可回收资源。这个更宽泛的描述，不会推翻完工墙使用 Mining 的具体回复，也没有确立任何材料都全额返还的规则。

## 操作前后各应观察什么？

大幅改建前先保留存档并检查准确目标。同一位置可能同时包含结构方块、家具、活跃订单和临时通路。如果只是想给支持搬动的家具换位置，不要把一个大范围清除选区当成与移动单件物品相同的动作。

完成后检查预期结果：被选的订单已取消、目标墙已移除，或家具已在新位置。不能只凭资源总数有变化，就推定得到某种保证的完整退款。[仓储与搬运](/zh/colonists/storage-filters-and-hauling/)解释了为什么返还材料仍可能需要可接收、能抵达的储存目的地。

## Copy 和 Clone 为什么要单独理解？

Demo 0.9.18 可以把支持的方块及对象连同设置克隆。更早的 **Copy Area** 会保留区域选择，并可保存为重复使用的计划。这些描述没有说明复制会搬走原对象，也没有说能绕过普通模式全部施工条件。[Building Editor 指南](/zh/building/building-editor-and-plans/)将可重复使用的设计与真正建造分开说明。

如果找不到预期功能，记录版本、模式、目标类型及是否已经完成。若问题是项目等材料或通路，应使用[停工检查](/zh/building/stalled-construction/)。没有来源保证每一栋旧完工建筑永远保留在历史列表，也不能承诺所有对象都有一样的移动按钮。

本文整理截至 Demo 0.9.18 的开发者说明，11月6日核对。没有进行个人拆除实测，不把这些步骤称为修复任何存档的方法，也不据此确认后续完整版的全部行为。
